# Поиск и оценка сообществ VK

[К README](../README.md) · [Рекомендации и ручная проверка](community-search-football-recommended.md) · [Отклонённые сообщества](community-search-football-rejected.md)

> [!IMPORTANT]
> VK Ads MCP автоматически ищет публичные сообщества по рекламному брифу, применяет фильтры по географии, тематике и типу аудитории, анализирует кандидатов и сортирует их по баллам и статусам. В результате пользователь получает структурированный список с причинами отбора и отклонения без ручного просмотра всей выдачи VK.
>
> Баллы и статусы помогают выбирать площадки, но не предсказывают результат рекламной кампании. Публичные данные VK могут быть неполными, а состав подписчиков не всегда можно определить точно. Перед расходованием бюджета проверьте итоговый список вручную: изучите тематику, географию и активность сообщества, условия размещения и соответствие аудитории вашему предложению. Начните с ограниченного теста и оценивайте фактические показатели рекламы. Решение о запуске, настройках и расходах принимает пользователь.

## Подключение поиска сообществ

### Что устанавливается

В установщик VK Ads MCP уже добавлено готовое приложение VK для авторизации поиска публичных сообществ. По умолчанию выбран вариант «Legacy OAuth — встроенное приложение». Создавать своё приложение VK для этого режима не нужно.

Поиск сообществ использует отдельную авторизацию Core VK API. Токен рекламного кабинета VK Ads для такого поиска не применяется. Установщик хранит оба подключения локально и не выводит токены через MCP.

### Как пройти авторизацию

1. Запустите установщик:

   ```bash
   npx --yes github:sergeylopukhov/vk-ads-mcp-all-in-one
   ```

2. Введите `client_id` и `client_secret` кабинета VK Рекламы.
3. На вопрос «Подключить поиск и анализ публичных сообществ VK?» выберите «Подключить».
4. Оставьте вариант «Legacy OAuth — встроенное приложение».
5. В поле `VK client_id приложения` нажмите Enter. Установщик подставит встроенное приложение.
6. В открывшемся окне войдите во VK и разрешите доступ.
7. После перехода на `oauth.vk.ru/blank.html` скопируйте полный адрес страницы из адресной строки и вставьте его в терминал.
8. Выберите MCP-клиенты, завершите установку и перезапустите их.

> [!WARNING]
> Полный адрес страницы после авторизации содержит токен. Не отправляйте его в чат, не сохраняйте в документах и не публикуйте в GitHub. Вставляйте адрес только в запрос установщика.

Если встроенное приложение не подходит, установщик позволяет выбрать VK ID OAuth со своим приложением. Для обычного поиска сообществ достаточно встроенного варианта.

### Как проверить подключение

Отдельного инструмента «проверить токен сообществ» у сервера нет. Проверка выполняется безопасным чтением публичных данных. Отправьте агенту:

```text
Проверь, доступен ли поиск публичных сообществ VK.
Найди несколько сообществ о городских мероприятиях.
Это обычный тематический поиск, рекламу не настраивай и ничего не меняй.
```

Агент должен выбрать режим `topic_discovery` и вызвать один из инструментов чтения, например `vk_find_community_candidates`. Успешный ответ VK подтверждает, что поиск доступен. Ошибка об отсутствующем `VK_API_TOKEN` означает, что авторизацию сообществ нужно пройти заново.

## Как подготовить рекламный запрос

Пользователю не нужно знать названия полей MCP, веса скоринга или лимиты страниц. Достаточно описать задачу обычным языком:

```text
У меня есть детская футбольная секция в Домодедове.
Найди релевантные сообщества для рекламы через VK Ads MCP.
```

Короткий запрос годится для начала диалога, но не для немедленного поиска. Перед обращением к VK агент должен выяснить:

| Что уточнить | Зачем это нужно |
| --- | --- |
| Товар или услуга | Чтобы сервер понимал, что рекламируется |
| Целевое действие | Чтобы отличить общую тематику от намерения записаться, купить или обратиться |
| Покупатель | Чтобы искать сообщества людей, принимающих решение |
| Получатель товара или услуги | Покупатель и пользователь могут быть разными людьми |
| Потребности и события перед покупкой | Они дают запросы о реальной аудитории, а не только о продавцах |
| География | Чтобы не рекомендовать сообщество из другого города |
| Отношение к конкурентам | Их подписчики могут быть полезны не в каждой нише |
| Поставщики и специалисты | Чтобы не принять продавцов услуги за покупателей |
| Исключения | Чтобы убрать вакансии, магазины, фан-группы и другие ложные совпадения |

Для рекламного исследования обязательны предложение, целевое действие, целевая аудитория и подтверждённая политика конкурентов. Если данных не хватает, сервер возвращает `needs_clarification` и не обращается к VK.

### Короткие примеры

```text
Ищу сообщества для рекламы семейного кафе в Подольске.
Решение принимают родители детей 4–12 лет.
Цель — бронирование дня рождения.
Аудиторию других кафе показывай отдельно для ручной проверки.
```

```text
Продвигаю интернет-магазин пряжи по России.
Покупатели — люди, которые вяжут для себя и на заказ.
Ищи сообщества о вязании, схемах и амигуруми.
Магазины пряжи считаются конкурентами и не должны попадать в основные рекомендации.
```

```text
Найди публичные сообщества о благоустройстве Домодедова.
Это тематический поиск, не рекламная оценка.
```

Последний запрос запускается как `topic_discovery`. Рекламный бриф для него не нужен, а результат нельзя называть готовой рекламной аудиторией.

## Как сервер ищет и оценивает сообщества

### От запроса к кандидатам

Агент переводит ответы пользователя в поисковую стратегию:

1. Отделяет покупателей от поставщиков, партнёров и конкурентов.
2. Формирует несколько запросов о покупателях, потребностях, событиях и местных организациях.
3. Передаёт серверу рекламный контекст и политику конкурентов.
4. Сервер проверяет бриф и стратегию до обращения к VK.
5. `groups.search` выполняется по релевантности VK и по числу участников.
6. Результаты разных запросов объединяются по ID сообщества.
7. Сервер читает публичное описание, число участников и доступные записи.
8. Кандидат получает балл, тип связи с аудиторией и итоговый статус.

Одинаковые слова в названии услуги и сообщества не доказывают наличие покупателей. Например, футбольная школа совпадает с темой детского футбола, но продаёт ту же услугу. При политике `exclude` она считается конкурентом и отклоняется.

### Типы связи с аудиторией

| Тип | Что означает | Максимальный статус по умолчанию |
| --- | --- | --- |
| `target_audience` | В сообществе подтверждены покупатели или лица, принимающие решение | `recommended` |
| `adjacent_audience` | Участники близки к покупателю по потребности, событию или детскому досугу | `recommended` или `review` |
| `partner` | Школа, детский сад, площадка или организация, с которой обычно нужно договариваться | `review` |
| `competitor` | Сообщество продаёт сходный товар или услугу | Зависит от подтверждённой политики |
| `provider` | Поставщик или специалист, которого нельзя принимать за покупателя | `rejected` |
| `irrelevant` | Тематика не соответствует выбранной аудитории | `rejected` |
| `unknown` | Связь с покупателями не подтверждена | Не получает `recommended` |

### Когда подходят конкуренты

У подписчиков магазинов смартфонов может быть явный интерес к покупке электроники. Для рекламы другого магазина такая аудитория бывает полезной. Сервер помещает её в отдельный кластер «Аудитория конкурентов», если пользователь явно разрешил этот вариант.

Для фотографа, психолога, врача, юриста, репетитора или мастера красоты выбор сильнее зависит от доверия к конкретному специалисту. Подписка на конкурента здесь хуже подтверждает готовность выбрать другого исполнителя. При высоком уровне личного выбора конкуренты не получают автоматическую рекомендацию и требуют отдельного подтверждения.

Политика конкурентов не определяется по умолчанию. Возможны три решения:

- `exclude` — отклонять конкурентов;
- `review` — показывать отдельным списком;
- `include` — учитывать как отдельную рекламную аудиторию.

## Баллы и статусы

### Из чего складывается оценка

Скоринг `community-research-v4` нормализует результат до шкалы 0–100. В исследовании могут учитываться:

- совпадения в названии, описании и публичных записях;
- признаки намерения: запись, пробное занятие, поиск услуги;
- свежесть и частота публикаций;
- доля тематических записей;
- совпадение с целевыми кластерами;
- минус-слова, неактивность, закрытость и другие риски.

Стандартные пределы положительных компонентов:

| Компонент | Максимум |
| --- | ---: |
| Термины в названии | 20 |
| Термины в описании | 20 |
| Термины в публикациях | 20 |
| Свежая активность | 15 |
| Доля тематических публикаций | 20 |
| Признаки намерения | 15 |

Эти пределы не нужно складывать вручную. Сервер применяет нормализацию, штрафы и обязательные правила допуска. Размер сообщества сам по себе не добавляет баллы релевантности.

### Как читать статусы

| Статус | Стандартное правило | Что делать пользователю |
| --- | --- | --- |
| `recommended` | Обычно от 45 баллов, есть сильный целевой сигнал и подтверждена связь с покупателями | Проверить площадку и условия размещения |
| `review` | Обычно от 30 баллов или действует ограничение по типу связи и рискам | Открыть сообщество и решить вручную |
| `rejected` | Меньше 30 баллов либо сработало обязательное отклонение | Не использовать без пересмотра стратегии |

Порог рекомендации по умолчанию равен 45, ручной проверки — 30. Пользователь может попросить другой порог обычной фразой: «Покажи сообщества от 40 баллов». Пересчёт сохранённого исследования не обращается к VK повторно.

Высокий балл не отменяет ручную проверку. В фактическом примере клиника и больница получили `recommended`, поскольку в публикациях есть родители, мамы и дети. Это реальные сигналы аудитории, но они не доказывают уместность рекламы футбольной секции в медицинском сообществе. С другой стороны, группа «Мамы Домодедово» получила 44 балла и статус `review`, хотя её аудитория соответствует покупателю гораздо точнее.

## Режимы поиска

| Режим | Как работает | Когда выбирать |
| --- | --- | --- |
| `efficient` | Оценивает метаданные всех найденных кандидатов, начинает глубокий анализ с разнообразной выборки из 100 сообществ и продолжает пакетами по 25 до стабилизации результата, достижения цели, отсутствия прироста или конца очереди. Фиксированного предела в 300 кандидатов нет | Для обычного исследования |
| `exhaustive` | Передаёт всех найденных кандидатов в очередь глубокого анализа | Для максимально широкого прохода |

Название `exhaustive` не гарантирует абсолютную полноту исходной выдачи VK: провайдер может ограничить поиск или вернуть ошибку. Однако сервер не применяет к этому режиму адаптивную остановку по стабильности или отсутствию прироста. Финальный ответ всегда нужно проверять по полям `exhaustive`, `stop_reason`, `analyzed`, `skipped` и `remaining_discovery`.

## Ограничения поиска VK

- VK возвращает не больше 1 000 результатов для одной комбинации запроса и сортировки.
- Сервер просматривает до 10 страниц и до 1 000 кандидатов на запрос.
- Один запрос выполняется по релевантности и по числу участников, затем результаты объединяются.
- Число, которое VK сообщает для разных запросов, содержит повторы. Количество уникальных ID после объединения меньше.
- Город берётся из настроек сообщества. Он может быть не указан, указан неверно или относиться только к владельцу страницы.
- Закрытые и удалённые сообщества дают меньше данных для оценки.
- Недоступные или редкие публикации снижают надёжность анализа.
- Поисковая выдача меняется со временем и зависит от формулировок.
- Режим `exhaustive` может закончиться с `exhaustive=false`, если получение исходной выборки было ограничено VK или заданным поисковым бюджетом.

Найденный список нельзя считать полным реестром сообществ VK. Он отражает фактическую выдачу провайдера, заданные запросы, доступные публичные данные и момент запуска.

## Пример: детская футбольная секция в Домодедове

### Исходный запрос

```text
У меня есть детская футбольная секция в Домодедове. Найди релевантные сообщества для рекламы через VK Ads MCP.
```

В исходный запрос не добавлялись возраст, описание покупателя, перечень сообществ или политика конкурентов.

### Первый ответ агента

Агент не передал запрос в VK. Он сообщил, что рекламный бриф неполный, и предложил выбрать способ ответа:

> Нужно уточнить несколько параметров поиска. Ответить на вопросы в чате или открыть интерактивный опросник?

Пользователь выбрал интерактивный опросник. До сохранения ответов обращений к VK не было.

### Заданные вопросы и ответы

| Вопрос | Ответ пользователя |
| --- | --- |
| Для детей какого возраста работает секция? | 3–5, 6–9, 10–13 и 14–17 лет |
| Кто обычно принимает решение о записи? | Родители или опекуны |
| Какое действие должно стать результатом рекламы? | Запись на пробное занятие |
| Какую территорию обслуживает секция? | Весь городской округ Домодедово |
| Можно ли рассматривать подписчиков других детских футбольных секций? | Нет, исключить конкурентов |
| Какие потребности приводят родителей в секцию? | Занятия после школы или детского сада; физическое развитие; интерес к футболу; команда, общение и дисциплина |
| Какие местные сообщества допустимо рассматривать? | Родители и группы мам; школы и детские сады; детские занятия, события и досуг |
| Какие тематики нужно исключить? | Профессиональные клубы; фан-группы и новости; взрослые лиги; вакансии и сообщества тренеров |
| Насколько широкий поиск нужен? | Максимально широкий |

### Стратегия после уточнений

| Часть стратегии | Решение |
| --- | --- |
| Назначение | Поиск рекламной аудитории |
| Предложение | Детская футбольная секция для детей 3–17 лет |
| Целевое действие | Запись на пробное занятие |
| Покупатель | Родители и опекуны |
| География | Городской округ Домодедово; в итоговом запуске применён городской фильтр VK |
| Целевая аудитория | Родители, мамы, семьи с детьми |
| Смежная аудитория | Детские центры, клубы, досуг, мероприятия и детский спорт |
| Партнёры | Школы и детские сады |
| Конкуренты | Другие футбольные школы, секции и академии; политика `exclude` |
| Режим | `exhaustive` |
| Пороги | `recommended` от 45, `review` от 30 |

Поисковые запросы:

```text
родители дети Домодедово
мамы Домодедово дети
школы детские сады Домодедово
детские занятия досуг Домодедово
детские мероприятия Домодедово
детский спорт Домодедово
куда отдать ребенка Домодедово
```

### Что было передано MCP-серверу

Агент вызвал `vk_start_community_research` с назначением `advertising_audience`. В запросе были переданы предложение, целевое действие, покупатель, причины обращения, география, явный запрет конкурентов, целевые и партнёрские термины, семь поисковых запросов, мягкие минус-слова и режим `exhaustive`.

Ключевая часть задания:

```json
{
  "research_context": {
    "purpose": "advertising_audience",
    "offer": "Детская футбольная секция для детей 3–17 лет",
    "conversion_action": "Запись на пробное занятие",
    "buyer_roles": ["родители", "опекуны"],
    "geography": "городской округ Домодедово",
    "competitor_policy": "exclude",
    "competitor_policy_confirmed": true
  },
  "country_id": 1,
  "city_id": 1054308,
  "analysis_policy": {
    "mode": "exhaustive"
  }
}
```

Перед запуском сервер вернул `preflight.status=ready`: обязательные поля заполнены, ошибок стратегии нет.

## Как проверить, что рекламный кабинет не изменялся

Инструменты исследования сообществ помечены как `read`. Они используют Core VK API и читают публичные данные. В этом примере вызывались только:

- `vk_start_community_research`;
- `vk_get_community_research_progress`;
- `vk_get_community_research_run`.

Инструменты создания или изменения кампаний, групп объявлений, объявлений, аудиторий и других рекламных объектов не вызывались. С начала исследования в локальном журнале VK Ads не появилось ни одной операции подготовки или записи.

Для собственного запроса заранее напишите агенту:

```text
Проведи только read-only исследование публичных сообществ.
Не создавай и не изменяй кампании, объявления, аудитории и другие рекламные объекты.
В конце перечисли вызванные MCP-инструменты.
```

Если в списке есть только инструменты чтения сообществ, исследование не меняло рекламный кабинет.
