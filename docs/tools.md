## Сообщества VK

Инструменты используют отдельный токен Core VK API и не меняют рекламный кабинет. Все десять инструментов прошли точную live-проверку. Сервер не содержит отраслевых пресетов: запросы, исключения, веса и кластеры задаются для каждой задачи.

По умолчанию сервер выполняет каждый запрос дважды: по релевантности VK и по числу участников. Для каждого режима доступны до 10 страниц и 1000 результатов. Все найденные ID объединяются и очищаются от дублей. Страна и город не ограничиваются, пока пользователь явно не задаст географию.

В режиме `efficient`, который используется по умолчанию, сервер оценивает метаданные всех найденных сообществ без загрузки публикаций и ранжирует доступный пул. Анализ начинается с разнообразной выборки из 100 кандидатов и продолжается пакетами по 25, пока верхняя выдача не стабилизируется, не будет достигнуто целевое количество результатов, несколько пакетов не пройдут без прироста или не закончится очередь. В начало попадают лучшие тематические результаты, небольшие профильные сообщества, выдача каждого запроса и исследовательская выборка. Размер аудитории не добавляет баллы релевантности.

Полный анализ включается через `analysis_policy.mode=exhaustive`. Поле `max_candidates` принимается для совместимости, но больше не ограничивает число глубоких проверок. Поле `exhaustive` показывает, проверена ли вся фактически полученная выборка. `stop_reason` различает доказанную стабильность верхней выдачи, достижение целевого количества, отсутствие прироста и полный проход. `estimated_wall_requests_saved` показывает, сколько запросов публикаций не потребовалось.

`search_budget` позволяет уменьшить число страниц и кандидатов для быстрого теста. `search_sort=both` включает оба режима, `relevance` оставляет только релевантность VK, `members` — сортировку по числу участников. Положительные и отрицательные термины учитывают границы слов, безопасные русские словоформы и перестановку слов в короткой фразе. `substring` сохраняет буквальный поиск подстроки для минус-слов.

Уровни `strong`, `medium` и `weak` задаются в `term_strengths`. Одиночный слабый термин не делает публикацию тематической; стандартный минимум — два слабых сигнала. `concepts` объединяет синонимы и перефразировки одного понятия без повторного начисления баллов. `contextual_signals` учитывает неоднозначный термин только рядом с заданным якорем. `negative_clusters` задаёт отраслевые отрицательные классы и пороги их доли в публикациях. Эти правила передаются в запросе и подходят для любой тематики.

`intent_terms` описывает намерение аудитории, а `compatibility_terms` отмечает кандидата для ручной проверки без автоматического исключения. Если настроены сильные понятия или целевые кластеры, рекомендация без их подтверждения запрещена. Риски из `recommendation_blockers` также не позволяют присвоить статус `recommended`.

Активность считается отдельно за 30 и 90 дней по последним 100 публикациям. Результат содержит число публикаций, недельную частоту, медианную недельную частоту за 90 дней и дату последней публикации.

По умолчанию `exclude_policy=soft`: минус-слово добавляет риск, но сообщество остаётся в результате. Совпадение в названии или описании и доля совпадений в публикациях оцениваются отдельно. Штраф публикаций растёт пропорционально их доле. `exclude_policy=hard` полностью удаляет совпадения в метаданных и используется только по явному решению пользователя.

Итоговый снимок `community-research-v4` возвращает исходный `raw_score`, нормализованный до диапазона 0–100 `normalized_score` и совместимое поле `score`. Компоненты показывают релевантность контента, намерение аудитории, активность, соответствие профиля и риск исключений. Для каждого проанализированного кандидата указаны подтверждённые понятия, контекстные сигналы, отрицательные кластеры, блокирующие риски и причина статуса. Не попавшие в глубокий анализ кандидаты возвращаются отдельно с причиной пропуска.

Высокоуровневые инструменты требуют явного `research_context.purpose`. Для `advertising_audience` сервер до обращения к VK проверяет предложение, целевое действие, покупателя, события перед покупкой, географию, подтверждённую политику конкурентов и исключаемых поставщиков. Неполный бриф возвращает `needs_clarification`, а стратегия только из поставщиков — `invalid_strategy`. Результаты содержат `audience_relationship`, причины классификации, покупательские сигналы, признаки поставщика или конкурента и применённую политику конкурентов.

Стандартный порог рекомендации — 45 баллов, ручной проверки — 30. Их можно изменить через `scoring_rules.min_score` и `scoring_rules.review_min_score`; второй порог не должен превышать первый.

Снимок хранит только производные совпадения и счётчики, без текстов публикаций. Свежие показатели используются повторно только при точном совпадении терминов, понятий, контекстных правил, отрицательных кластеров, режима совпадения и глубины анализа. Если локальный пересчёт требует сигналов, которых не было в исходном анализе, результат получает признак неполноты.

Каждый ключ `term_weights` и `term_strengths` должен точно совпадать с элементом `scoring_rules.terms`; ключ `intent_term_weights` — с элементом `intent_terms`. Все веса, включая штрафы, передаются неотрицательными величинами: вычитание выполняет сервер. Порог `min_score` должен быть достижим при заданной сумме положительных весов, а `review_min_score` не может его превышать.

Порог рекомендации и порог ручной проверки можно менять отдельно. Сохранённое исследование пересчитывается по новым порогам, весам и кластерам без повторного обращения к VK, если все нужные термины уже были проанализированы. Расширение географии, поискового бюджета, списка запросов или исходного пула запускает новый поиск.

Если подходящих сообществ меньше, чем запросил пользователь, устанавливаемый навык показывает текущие пороги и причину дефицита. Затем предлагает расширить поиск, изменить баллы, уточнить запросы или ослабить конкретный фильтр. Порог и исключения не меняются без выбора пользователя.

Если для начального брифа требуется пять и более уточнений, навык предлагает ответить в чате или установить [интерактивный опросник](https://github.com/sergeylopukhov/interactive-project-questionnaire). Установка выполняется только с согласия пользователя через универсальный установщик опросника. При 1–4 уточнениях навык задаёт вопросы в чате.

## Как безопасно работать

1. Начните с запроса: «Проверь подключение к VK Рекламе и покажи текущий рекламный кабинет. Ничего не меняй».
2. Опишите нужное изменение и попросите показать подготовленное действие до записи.
3. При `ready=false` вы увидите условия, которые мешают выполнить действие. Исправление связанного объекта с `requiresConfirmation=true` потребует отдельного согласия.
4. При `ready=true` подтвердите точное действие. Сервер выполнит одну операцию и проверит результат чтением, если VK Ads поддерживает такую проверку.
5. Не используйте инструменты со статусом `⛔️` для изменений в рабочем кабинете.

`vk_ads_action_prepare` принимает только действия с проверенным контрактом. Универсального инструмента для произвольных запросов нет.
